# Graph Info Pipeline — KV Mapping & Validation

A data wrangling toolkit that reads an ML pipeline JSON file (`graph_info.py`),
generates a flat key-value Excel sheet, and validates the output for anomalies.

---

## Folder Structure

```
your_folder/
├── graph_info.py           ← Source data  (JSON — ML pipeline definition)
├── generate_graph_kv.py    ← Step 1: generates graph_kv_gen3.xlsx from JSON
├── validate_graph_kv.py    ← Step 2: validates JSON + xlsx for anomalies
├── graph_kv_gen3.xlsx      ← Output: generated by generate_graph_kv.py
└── README.md               ← This file
```

---

## What is `graph_info.py`?

A JSON file (named with `.py` extension) that defines a complete **ML pipeline experiment**.
It contains 3 top-level keys:

| Key | Description |
|---|---|
| `experiment_id` | Unique hex ID for the entire pipeline run |
| `nodes[]` | 11 pipeline steps — preprocessing + ML models |
| `edges[]` | 10 connections between steps (the flow arrows) |

### The 11 Nodes

**Data Preprocessing (5 steps)**

| Node | What it does |
|---|---|
| `Source_2` | Connects to PostgreSQL (`medicine_data` table) and loads 10,000 rows |
| `Missing_Values_3` | Removes rows with missing values |
| `Duplicates_Removal_4` | Removes duplicate rows |
| `Encoding_6` | Label-encodes 6 text columns |
| `Scaling_7` | Standard-scales the same 6 columns |

**ML Algorithms (6 models — trained in parallel)**

| Node | Algorithm |
|---|---|
| `KNN_Regression_10` | K-Nearest Neighbours Regression |
| `Decision_Tree_Regression_11` | Decision Tree Regression |
| `Bagging_Regression_12` | Bagging Ensemble Regression |
| `Boosting_Regression_13` | AdaBoost Regression |
| `Random_Forest_Regression_14` | Random Forest Regression |
| `Linear_Regression_15` | Linear Regression |

### Pipeline Flow

```
Source_2
  └─► Missing_Values_3
        └─► Duplicates_Removal_4
              └─► Encoding_6
                    └─► Scaling_7
                          ├─► KNN_Regression_10
                          ├─► Decision_Tree_Regression_11
                          ├─► Bagging_Regression_12
                          ├─► Boosting_Regression_13
                          ├─► Random_Forest_Regression_14
                          └─► Linear_Regression_15
```

## Usage

### Step 1 — Generate the Excel file

```bash
python generate_graph_kv.py
```

Default paths:
- Input  : `graph_info.py`
- Output : `graph_kv_gen3.xlsx`

Custom paths:

```bash
python generate_graph_kv.py --input graph_info.py --output graph_kv_gen3.xlsx
```

**What it produces — 6 columns:**

| Column | Description |
|---|---|
| `NODE` | JSON key name (e.g. `transformation_type`, `n_neighbors`) |
| `NODE TYPE` | Section: `node`, `node_details`, `node_type`, `edge`, `edge_type` |
| `edge` | Key or relationship name |
| `edge type` | Parent section (e.g. `transformation_properties`, `mlflow_tracking_properties`) |
| `NODE B (VALUE)` | Actual value from JSON |
| `NODE TYPE B` | Key name echo (mirrors column 1 or 3) |

**Key behaviour:**

- Comma-separated values (e.g. `columns` field, `True,False`) → **split into individual rows**
- MLflow `property_value` arrays → **exploded** one param per row via `json.loads()`
- Each node is grouped with a coloured section divider row

---

### Step 2 — Validate the output

```bash
python validate_graph_kv.py
```

Custom paths:

```bash
python validate_graph_kv.py --json graph_info.py --xlsx graph_kv_gen3.xlsx
```

**Console output only — no files written.**

## Anomaly Checks Performed

### Value-level checks (run on every field)

| Check | Severity | What it detects |
|---|---|---|
| `COMMA_SEPARATED_VALUE` | 🔴 HIGH | Values with commas that need splitting into rows |
| `NULL_VALUE` | 🟡 MEDIUM | Fields that are `None` / null |
| `SINGLE_QUOTE_WRAPPED` | 🟡 MEDIUM | Values like `'short_composition2'` with extra quotes |
| `JSON_ENCODED_STRING` | 🟡 MEDIUM | Values that are raw JSON array strings `["a","b"]` |
| `EMPTY_STRING` | 🔵 LOW | Fields that are empty `""` or whitespace only |
| `BOOL_AS_STRING` | 🔵 LOW | `True` / `False` stored as strings |
| `INTEGER_AS_STRING` | 🔵 LOW | Numbers like `"10"`, `"20"` stored as strings |
| `FLOAT_AS_STRING` | 🔵 LOW | Decimals like `"0.3"`, `"0.6"` stored as strings |

### Cross-node checks

| Check | Severity | What it detects |
|---|---|---|
| `TYPE_INCONSISTENCY` | 🔴 HIGH | Same key has different Python types across nodes |
| `DANGLING_EDGE` | 🔴 HIGH | Edge source/target references a non-existent node id |
| `MISSING_MLFLOW` | 🔴 HIGH | ML algorithm node missing `mlflow_tracking_properties` |

### xlsx cross-check

Compares every expected leaf value from `graph_info.py` against the
`NODE B (VALUE)` column in the generated xlsx — flags any missing values.

---

## Known Data Anomalies in `graph_info.py`

These are **expected findings** — the validate script will always report them:

| Issue | Location | Detail |
|---|---|---|
| `connection_type` is `null` | 10 of 11 nodes | Only `Source_2` has `connection_type = postgres` |
| `description` is `""` | All 11 nodes | Description field is empty everywhere |
| `sourceHandle` / `targetHandle` are `null` | All 10 edges | UI positioning not set |
| Comma-separated `columns` field | `Encoding_6`, `Scaling_7` | Intentional — split into rows by generator |
| `True,False` in `fit_intercept` / `positive` | `Linear_Regression_15` | Split into separate rows by generator |
| Booleans as strings | Multiple ML nodes | e.g. `"True"`, `"False"` for `bootstrap`, `is_cross_validation_enable` |
| Integers as strings | Multiple ML nodes | e.g. `"10"`, `"20"` for `n_neighbors`, `max_depth` |

## File Descriptions

### `generate_graph_kv.py`

| Function | Purpose |
|---|---|
| `extract_rows(data)` | Walks the JSON and produces one `Row` per atomic value |
| `_split_columns(raw)` | Splits comma-separated values into individual items |
| `_is_column_list(raw)` | Detects whether a value needs splitting |
| `write_excel(rows, output_path)` | Writes the formatted xlsx with section dividers |
| `main()` | CLI entry point |

### `validate_graph_kv.py`

| Function | Purpose |
|---|---|
| `scan_json(data)` | Runs all value-level checks across every field |
| `check_*` functions | Individual anomaly detectors (null, comma, bool, etc.) |
| `check_type_inconsistency(data)` | Cross-node type check |
| `check_edge_integrity(data)` | Validates edge source/target references |
| `validate_xlsx(path, data)` | Cross-checks xlsx against JSON source |
| `print_report()` | Prints colour-coded console report |

## Author Notes

- `graph_info.py` uses `.py` extension but contains **pure JSON** — open it as JSON
- The `node.type` field is always `"textUpdater"` — this is a React UI internal label, **not** the node type for data purposes; use `transformation_type` instead
- `node_details` mirrors several fields from `node` — this is by design in the source system
- All 6 ML algorithm nodes have identical MLflow output metrics (`Mean_squared_error`, `R2_Score`, etc.)
